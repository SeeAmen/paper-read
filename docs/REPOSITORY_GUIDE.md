# 仓库使用规范

本文档定义仓库的长期维护约定。`templates/paper/` 是新论文目录的唯一标准模板。

## 1. 每篇论文的资产链

每篇论文都按同一条知识资产链处理：

1. **source**：原文、权威来源、版本和获取信息。
2. **translation**：严格沿原文章节逐节翻译。
3. **terminology**：术语、正式定义、工程含义和大白话解释。
4. **notes**：阅读地图、机制解释、公式拆解、问题和章节总结。
5. **experiments**：最小可复现实验、代码、断言和观察结果。
6. **practice**：工程设计、架构映射、适用边界和落地方案。
7. **comparisons**：与其他论文、框架或同类方案进行比较。

目录可以增加，但以上七类资产和论文根 README 不得省略。暂无内容的目录保留模板 README，并注明状态。

## 2. 路径与命名

论文路径：

```text
papers/<domain>/<organization>/<paper-slug>/
```

约定：

- 路径统一使用小写英文和连字符。
- `domain` 表示稳定研究领域，如 `agent-harness`、`llm-inference`。
- `organization` 使用主要作者机构或发布组织；无法确定时使用 `independent`。
- `paper-slug` 使用简短、稳定、可辨识的论文英文短名。
- 翻译文件按原文章节编号，例如 `00-title-and-abstract.md`、`01-introduction.md`。
- 实验按执行顺序编号，例如 `exp-01-effect-rollback.md`。

路径发布后尽量不改名；确需调整时同步修复所有相对链接和主题比较索引。

## 3. 论文元信息与状态

每篇论文的根 `README.md` 至少包含：

- 题目、作者、机构、发布日期和当前版本；
- DOI、arXiv、会议或官方仓库等权威来源；
- 研究领域与关键词；
- 阅读状态和最近更新时间；
- 一句话结论、核心问题与核心贡献；
- 七类资产的导航。

阅读状态只使用以下值：

| 状态 | 含义 |
|---|---|
| `待读` | 已登记，尚未开始 |
| `阅读中` | 正在翻译、做笔记或验证 |
| `已通读` | 已完成正文阅读，但实验或实践未完成 |
| `已验证` | 关键结论已通过实验或外部证据验证 |
| `已归档` | 暂停维护或仅保留历史参考 |

## 4. 原文与版本规范

- `source/SOURCE.md` 记录权威链接、获取日期、文件名、许可信息和可用的校验值。
- `source/VERSIONS.md` 记录版本日期、来源、关键变化，以及翻译、笔记、实验是否需要同步。
- 仅在作者或出版方许可允许时提交 PDF；不确定时只提交来源信息，不提交全文。
- 不要用后来的版本静默替换旧 PDF。先登记版本变化，再更新文件和相关研究资产。
- 大型附件优先放在外部可持续存储中，并在 `SOURCE.md` 中记录定位信息。

## 5. 翻译规范

翻译按原文章节组织，并尽量保留标题、段落、公式、图表和引用的对应关系。推荐结构：

1. 原文位置与版本；
2. 中文翻译；
3. 术语说明；
4. 大白话解释；
5. 软件工程映射；
6. 领域映射；
7. 可验证问题。

“中文翻译”只表达原文内容。补充背景、类比、批评或推导必须放在明确标记的解释区，不能混入翻译正文。

## 6. 术语规范

本文术语表至少包含：

- 英文原词；
- 推荐中文译法和可接受的其他译法；
- 正式定义；
- 工程含义；
- 大白话解释；
- 首次出现章节；
- 来源或定义依据。

跨多篇论文通用的术语，同时加入 `docs/GLOSSARY.md`。出现译法冲突时保留不同语境，不强行合并。

## 7. 笔记与证据标签

阅读笔记至少维护阅读地图和开放问题。所有超出原文直译的结论使用以下标签：

- `【论文原文支持】`：能定位到论文原文；
- `【工程推导】`：由论文机制推导出的工程含义；
- `【个人设计】`：面向具体系统的设计方案；
- `【待验证】`：目前缺少证据或实验支持。

关键主张应附章节、页码、公式、图表、实验或外部来源，避免无法回溯的“印象式结论”。

## 8. 实验规范

每个实验至少写明：

- 实验目的与对应论文机制；
- 环境、依赖、输入和前置条件；
- 最小实现与执行命令；
- 预期结果、实际结果和原始数据位置；
- 失败场景、偏差与复现限制；
- 对论文结论的支持、修正或反例。

代码优先放在该论文的 `experiments/` 下；跨论文复用的实验工具可以独立成项目，但必须从实验记录链接回去。

## 9. 工程实践规范

工程实践不是论文复述，应明确回答：

- 要解决的真实问题是什么；
- 哪些设计直接得到论文支持；
- 哪些是工程推导或个人设计；
- 适用边界、成本、风险和回滚方案是什么；
- 如何用 PoC、指标或线上观察验证。

## 10. 横向比较规范

单篇论文相关比较放在其 `comparisons/` 下；涉及三篇及以上论文或长期主题的比较放在仓库根 `comparisons/<topic>/` 下。

统一比较维度：

- 问题定义与目标；
- 核心抽象与理论假设；
- 生命周期、依赖和状态模型；
- 扩展、容错与回滚；
- 安全、权限与可观测性；
- 实验依据与成熟度；
- 工程复杂度、适用场景和局限性。

比较表之后必须给出依据、上下文和结论置信度，不能只给打分。

## 11. 提交与维护

- 一次提交聚焦一个论文、一个实验或一类模板变更。
- 提交信息建议使用：`paper: ...`、`translation: ...`、`experiment: ...`、`practice: ...`、`comparison: ...`、`docs: ...`。
- 新论文加入或状态变化时，同步更新 `papers/README.md`。
- 新增公共术语或主题比较时，同步维护对应根索引。
- 提交前完成 [`QUALITY_CHECKLIST.md`](QUALITY_CHECKLIST.md)。
