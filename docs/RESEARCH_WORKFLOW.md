# 论文研究工作流

## 阶段 0：登记

- 确认权威来源、作者、版本、发布日期和许可。
- 从 `templates/paper/` 创建目录。
- 在论文 README 与 `papers/README.md` 中标记为 `待读`。

## 阶段 1：建立阅读地图

- 浏览摘要、目录、图表、结论和参考文献。
- 记录论文要解决的问题、主要贡献、前置知识和阅读顺序。
- 把不理解或需要验证的内容写入 `notes/questions.md`。

完成条件：能用自己的话说明论文的问题、方法、证据和限制。

## 阶段 2：逐章翻译与术语同步

- 翻译按原文章节编号，不改变论证顺序。
- 每次遇到核心术语，同步更新本文术语表。
- 解释、类比和质疑进入笔记，不混入翻译正文。

完成条件：翻译可与原文章节一一对应，核心术语前后一致。

## 阶段 3：机制拆解

- 画出输入、状态、关键步骤和输出。
- 拆解核心公式、算法、系统组件或因果链。
- 标注论文明确支持的结论和仍需验证的假设。

完成条件：读者不阅读全文也能从阅读地图理解核心机制。

## 阶段 4：实验验证

- 优先设计最小、可证伪的实验。
- 固定环境与输入，记录预期和实际结果。
- 同时记录成功、失败和无法复现的部分。

完成条件：关键主张至少有论文证据、复现实验或明确的未验证标记。

## 阶段 5：工程落地

- 映射到真实系统问题和约束。
- 明确采用、改造或拒绝论文方案的理由。
- 设计 PoC、指标、风险控制和回滚路径。

完成条件：实践建议可执行，并能区分论文事实、工程推导和个人设计。

## 阶段 6：横向比较与沉淀

- 选择解决同一问题的论文或实现，按统一维度比较。
- 把跨论文稳定术语加入公共术语表。
- 更新论文状态、索引、最终结论和仍开放的问题。

完成条件：结论能说明适用条件和置信度，而不只是给出单一排名。

## 版本更新

发现新版本时：

1. 在 `source/VERSIONS.md` 登记；
2. 对比摘要、目录、关键公式、实验和结论；
3. 标记受影响的翻译、术语、笔记、实验和实践；
4. 完成同步后更新论文 README 中的版本与日期。
